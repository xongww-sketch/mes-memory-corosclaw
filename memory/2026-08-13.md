### 真凶：不是 SQL，是 n8n 的 O(N²)

熊旺跑了 EXPLAIN，一锤定音：
```
Execution Time: 336.987 ms   ← 跨5年只要 0.34 秒
Planning Time:   1.298 ms
```
执行计划理想：Nested Loop + Merge Join + Index Only Scan，无 Seq Scan / Hash Join / 落盘。

**数据库 0.34s，接口 240s → 慢的 99.86% 不在数据库。**

**真凶：`Edit Fields1`（Set 节点）**
```javascript
searchList = {{ JSON.stringify($input.all().map(el => el.json)) }}
```
- Set 节点默认对每个 input item 各求值一次
- 表达式里 `$input.all()` 每次序列化全部数据
- N 个 item × 每次 stringify 全部 N 条 = **O(N²)**
- 跨5年 7208 行 ≈ 5200万次对象序列化

**实测验证**（纯 JS 基准）：
| 行数 | Set 写法 | Code 写法 | 倍数 |
|---|---|---|---|
| 526 | 370ms | 1ms | 370x |
| 2000 | 6,465ms | 3ms | 2155x |
| 4000 | 19,836ms | 7ms | 2834x |

数据量涨13.7倍、耗时涨188倍 = 13.7² → **O(N²) 铁证**。

### 修复（V4）
```javascript
// Code 节点，runOnceForAllItems，只执行一次
const rows = $input.all().map(el => el.json);
return [{ json: { searchList: JSON.stringify(rows) } }];
```
SQL 一个字没改，只把 Set 换 Code。O(N²)→O(N)。

⚠️ **这个坑是原版就有的**，我 V3 原样保留才没治好。
